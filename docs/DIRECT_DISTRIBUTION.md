# Developer ID direct distribution

This guide is for a future direct-distribution release of Small Matter. It is
separate from Mac App Store Connect, TestFlight, App Review, and the immutable
v0.9.1 direct-distribution artifacts. Running these commands does not publish a
release or install over `/Applications/Small Matter.app`.

## Build and package

From a clean review checkout, use the Developer ID Release configuration:

```sh
./scripts/build_release.sh --signed --direct-dmg
```

Before building a version that shares a historical version/build number,
use a separate, new artifact directory. The release script **refuses to
overwrite existing ZIP/checksum pairs** for the version/build it produces;
historical `v0.9.1` artifacts must remain immutable. An existing output
collision is an error, never an invitation to delete or replace it.

The script uses a generic macOS destination with `ARCHS=arm64 x86_64` and
`ONLY_ACTIVE_ARCH=NO`. It rejects a missing `Developer ID Application`
identity, validates the app before packaging, accepts arm64/arm64e Apple
Silicon slices plus x86_64 Intel, rejects privileged helper
payloads, and writes a new DMG plus sidecars under `.release-artifacts/`:

```text
Small-Matter-VERSION-BUILD-macos.dmg
Small-Matter-VERSION-BUILD-macos.dmg.sha256
Small-Matter-VERSION-BUILD-macos.dmg.manifest.txt
Small-Matter-VERSION-BUILD-macos.dmg.manifest.txt.sha256
```

The DMG contains only:

```text
Small Matter.app/
Applications -> /Applications
```

The app's checked-in asset-catalog icon is preserved in the bundle and is the
Finder presentation. Finder layout is applied while the temporary writable
image is mounted: the app and Applications alias are placed side by side with
a 128-point icon size. A separate branded volume icon is intentionally not
claimed: the current Xcode 27 `iconutil` rejects both the repository iconset and
a system-generated iconset, so the builder records
`VOLUME_ICON=NOT_CUSTOMIZED_SYSTEM_ICONUTIL_UNAVAILABLE` and continues with the
reliably testable app icon.
If Finder automation is unavailable, the command fails rather than silently
producing an unpresented release image. For a non-GUI disposable test only,
pass `--skip-finder-layout`; the structure, icon, checksum, mount, and
unmount checks still run and the manifest records the explicit skip.

The image is created as HFS+ UDRW, configured, then converted to UDZO with
`zlib-level=9`. The builder refuses to overwrite an existing output, stages
with `mktemp`, uses `ditto --norsrc`, creates the Applications symlink itself,
and atomically moves only a validated converted image into the requested new
destination. It never deletes source apps or release artifacts.

The content manifest is repeatable for the same app input and records file
SHA-256 values, symlink targets, volume name, compression settings, and Finder
layout status. `hdiutil` owns filesystem metadata, compression container
metadata, and any Finder `.DS_Store`; those system-generated bytes can vary.
Therefore this workflow promises repeatable logical contents and validation,
not bitwise-identical DMG files. The DMG checksum always describes the exact
bytes produced by that run.

Unsigned local preparation is explicit and non-shippable:

```sh
./scripts/build_release.sh --prepare-only --direct-dmg --skip-finder-layout
```

This is useful only for structural qualification. It prints
`SIGNATURE=UNSIGNED_PREPARATION_ONLY`; it must not be described as a release.

## Verify a DMG

The verifier checks the exact image with `hdiutil`, validates its checksum
sidecar when present, mounts it read-only in a secure temporary directory, and
checks:

- the real `Small Matter.app` bundle and exact `/Applications` symlink;
- the in-bundle app icon contract and allowed root entries;
- absence of `.pkg`, `.mpkg`, installer images, setuid/setgid files, and the
  obsolete `TunixHelper`/LaunchDaemon payload;
- the app's Developer ID signature, hardened runtime, Team ID, empty direct
  entitlements, universal slices, credential markers, and bundle safety.

```sh
./scripts/verify_direct_dmg.sh \
  --dmg '.release-artifacts/Small-Matter-VERSION-BUILD-macos.dmg'
```

For a disposable unsigned fixture, add `--allow-unsigned`. That option cannot
be combined with `--gatekeeper`.

## Notarize the DMG

Notarization is a release-time external gate. Store credentials only in a safe
Keychain `notarytool` profile and provide its name through the environment:

```sh
TUNIX_NOTARYTOOL_PROFILE=direct-release \
  ./scripts/notarize_direct_dmg.sh \
  --dmg '.release-artifacts/Small-Matter-VERSION-BUILD-macos.dmg'
```

The script submits the exact DMG, waits for the result, staples and validates
the DMG ticket, refreshes only that new DMG's checksum sidecar, mounts the
stapled image, and runs `spctl --assess --type execute` against the extracted
app. Missing profile credentials produce `NOTARIZATION_UNAVAILABLE` in the
release record; they never produce a claimed notarized result.

## Disposable regression test

Run this on an owner's Mac after the source Release build can compile:

```sh
./scripts/test_direct_dmg.sh
```

The test uses a fresh temporary derived-data/artifact root, builds an actual
unsigned universal Release candidate, builds and inspects a disposable DMG,
mounts and unmounts it read-only, checks the manifest for installers, and
exercises rejection of a missing app. It removes only its own temporary root
on exit. It does not use an existing archive, installed app, historical asset,
or production quarantine as a fixture. If Xcode cannot produce the candidate,
the test fails with that build error and no packaging pass is inferred.

Release configuration currently sets `DEBUG_INFORMATION_FORMAT=none`, so no
dSYM is part of this direct DMG. If release debugging policy changes to emit a
dSYM, retain it as a separately checksummed release sidecar; never place it in
the installer image unless the package contract is intentionally changed.
